# ZeTer OS

<img src="app/assets/icons/zeter-logo.svg" alt="Логотип ZeTer OS" width="96" height="96" />

**ZeTer OS** — рабочее пространство для Windows с интерфейсом в стиле операционной системы: рабочие столы, окна, меню «Пуск», Проводник и приложения для повседневных задач. Проект объединяет Python/pywebview и HTML, CSS, JavaScript, чтобы один интерфейс работал как настольное приложение и в браузере.

![Интерфейс ZeTer OS: рабочий стол и приложения](docs/images/zeter-os-banner.png)

**Быстрые ссылки:** [Запустить онлайн](https://dkl.do.am/zeteros/index.html) · [Скачать для Windows](https://github.com/zeter1/ZeTer-OS/releases) · [История изменений](CHANGELOG.md) · [Сообщить об ошибке](https://github.com/zeter1/ZeTer-OS/issues) · [GitHub разработчика](https://github.com/zeter1)

**Версия исходников в `main`: 4.0.64 (19 октября 2026 года).** Версия определяется файлом [`app/js/core/version.js`](app/js/core/version.js). Актуальный готовый EXE ищите в [Releases](https://github.com/zeter1/ZeTer-OS/releases): исходники, Windows-релиз и публикация на uCoz не обязательно обновляются одновременно.

### Готовая Windows-версия (без Python)

> Релизы пока имеют статус **Prerelease** — предварительные сборки для тестирования.

1. Откройте [Releases](https://github.com/zeter1/ZeTer-OS/releases) и выберите нужный выпуск.
2. В разделе **Assets** скачайте файл `ZeTer-OS-<версия>-Windows-x64.zip`.
3. **Распакуйте весь ZIP** в отдельную папку и запустите `ZeTer-OS.exe`.

Python пользователю **не требуется**: он и остальные runtime-файлы включены в сборку. Но для графического интерфейса нужен **Microsoft Edge WebView2 Runtime**. Если его нет на компьютере, установите [официальный WebView2 Runtime от Microsoft](https://developer.microsoft.com/en-us/microsoft-edge/webview2/). Не переносите EXE отдельно от DLL, `app/`, `zeter-update.json` и других файлов распакованной папки.

EXE не подписан цифровой подписью издателя; предупреждения Windows/SmartScreen возможны. Загружайте сборки только из [релизов этого репозитория](https://github.com/zeter1/ZeTer-OS/releases).

#### Необязательно: проверка целостности ZIP

**Для установки и запуска программы файл SHA-256 не нужен.** Он полезен, если хотите дополнительно убедиться, что скачанный ZIP совпадает с опубликованным архивом.

1. В **Assets** того же релиза скачайте `ZeTer-OS-<версия>-Windows-x64.sha256.txt` рядом с ZIP.
2. Откройте `.sha256.txt`: в нём записана контрольная сумма архива.
3. Откройте PowerShell в папке с ZIP и выполните:

```powershell
Get-FileHash .\ZeTer-OS-*-Windows-x64.zip -Algorithm SHA256
```

Сравните значение `Hash` с контрольной суммой в TXT. Они должны совпадать. Несовпадение означает, что архив нужно скачать заново. Совпадение подтверждает целостность относительно опубликованной суммы, но само по себе не подтверждает личность издателя.

### Веб-версия

**Адрес:** https://dkl.do.am/zeteros/index.html

Открывается в браузере без Python и установки EXE. Веб-режим использует хранилище браузера (**IndexedDB**, с дополнительными механизмами восстановления) и отличается от локальной папки `data/` Windows-версии. Python bridge, управление Windows и некоторые операции с локальными документами доступны только в desktop-режиме.

Веб-приложение использует проверяемый комплект ресурсов и service worker: после публикации новой версии обычное открытие или F5 проверяет обновление; уже открытая вкладка уведомляет о нём без принудительной перезагрузки. При первом переходе со старой публикации могут потребоваться закрытие прежних вкладок и повторное открытие сайта. [Как устроена веб-публикация](docs/UCOZ.md).

**Важно:** данные браузера и Windows-приложения не синхронизируются автоматически. Очистка данных сайта/профиля браузера может удалить сохранённую работу: используйте экспорт и резервные копии.

## Возможности

- **Рабочий стол и навигация:** несколько рабочих пространств, Проводник, папки, окна, панель задач, меню «Пуск», ярлыки и настройка оформления.
- **Планирование:** заметки, календарь, задачи с проектами, категориями, доской и представлениями списка/обзора.
- **Работа с информацией:** таблицы, файлы, изображения, библиотека ссылок и библиотека промптов.
- **Учёт времени:** таймер с паузой, ручные записи, проекты и задачи, планирование через календарь, журнал, недельная статистика и экспорт CSV.
- **Подсчёты:** бизнес-калькуляторы с настраиваемым набором карточек.
- **Системные инструменты:** настройки, горячие клавиши, центр уведомлений, системный монитор с показателями и графиками.
- **Надёжность:** локальное сохранение состояния, экспорт данных, резервные копии, точки восстановления и «Центр безопасности».
- **Desktop-интеграция:** native API через `pywebview`, файловые операции и автозапуск вместе с Windows без обязательных прав администратора.

Редактирование импортированных **DOC/DOCX** в desktop-версии требует отдельно установленного **LibreOffice**. Возможности могут различаться в зависимости от режима запуска и опубликованной версии; подробности — во [встроенной справке](app/js/core/help-content.js) и [истории изменений](CHANGELOG.md).

## Как пользоваться

1. Откройте веб-версию либо запустите `ZeTer-OS.exe`.
2. Пройдите первоначальную настройку и создайте или выберите рабочий стол.
3. Открывайте нужные приложения через «Пуск», панель задач, ярлыки или Проводник.
4. Для важных данных настройте резервные копии и используйте экспорт; перед переносом, переустановкой или восстановлением создайте проверенную копию.
5. Проверяйте наличие новых функций и исправлений в [CHANGELOG.md](CHANGELOG.md). В Windows EXE доступна проверка обновлений в приложении.

## Запуск из исходников

Нужны Windows, Python 3 и `pywebview` из `requirements.txt`. В CI используется **Python 3.13**. Команды из PowerShell:

```powershell
git clone https://github.com/zeter1/ZeTer-OS.git
cd ZeTer-OS
py -3 -m pip install -r requirements.txt
py -3 run_zeter_os.py
```

Альтернативно запустите `start_zeter_os.cmd`. Это **Python-версия**, а не готовый EXE; не путайте её с ZIP из Releases. Подробная инструкция: [README_PYTHON.md](README_PYTHON.md).

## Где хранятся данные и как восстановиться

| Режим | Основное хранилище |
| --- | --- |
| Windows EXE / Python desktop | `data/zeter-os-state.json` (обычно рядом с приложением; путь может быть перенесён в настройках) |
| Браузер / PWA | IndexedDB текущего профиля и адреса сайта |

В desktop-версии резервные копии находятся в `data/backups/`, а диагностические сеансы — в папке **`Логи проблем/`** рядом с программой. Начните разбор ошибки с `Логи проблем/latest_run.json`, который указывает на журнал последнего сеанса. Для старых сборок возможен `data/logs/zeter-os.log`.

**Не удаляйте `data/`, резервные копии, IndexedDB или кэш PWA для «исправления запуска» без предварительного сохранения важных данных.** [Модель хранения](docs/DATA_MODEL.md) · [Диагностика](docs/TROUBLESHOOTING.md) · [Поддержка](SUPPORT.md).

## Обновления

- **Windows EXE:** проверяет доступность более новой версии через `updates.json` на GitHub Pages и предлагает установку; ZIP загружается из GitHub Releases после согласия пользователя. Пакет проверяется перед заменой файлов, предусмотрены восстановление и откат при ошибках. [Подробности и ограничения](docs/UPDATES.md).
- **Веб-версия:** проверяет опубликованный комплект веб-ресурсов; обновление вкладки и пользовательское состояние обрабатываются отдельно. [Инструкция uCoz](docs/UCOZ.md).
- **Исходники Python:** скачиваются или обновляются разработчиком отдельно; механизм обновления EXE не заменяет Python-проект.

Полная история проекта: **[CHANGELOG.md](CHANGELOG.md)**. Текст конкретной Windows-сборки: [Release Notes](RELEASE_NOTES_RU.md). Самый новый код не всегда равен версии последнего опубликованного ZIP.

## Архитектура

```text
ZeTer-OS/
├── run_zeter_os.py          # запуск Windows-окна, HTTP и native API
├── problem_logs.py          # структурированная диагностика
├── app_updater.py           # проверка и подготовка обновлений EXE
├── update_runner.py         # замена файлов, журнал и откат
├── app/
│   ├── index.html           # web-оболочка
│   ├── service-worker.js    # согласованные офлайн-комплекты
│   ├── css/                 # стили по функциональным зонам
│   └── js/
│       ├── app.js           # composition root: state/UI/integration
│       └── core/            # предметные и UI-модули
├── docs/                    # архитектура и эксплуатационные контракты
├── tools/                   # проверки, smoke-тесты и сборка
├── build_exe.bat            # нативная Windows x64-сборка
├── build_release.cmd        # отдельный Python portable ZIP
└── check_project.cmd       # проектная проверка
```

**Как это работает:** Python запускает локальный HTTP-сервер и окно `pywebview`; JavaScript-интерфейс связывается с native-возможностями через bridge. В браузере та же оболочка работает без Python API, с отдельным хранилищем. `app/js/app.js` связывает состояние и обработчики, а предметная логика распределена по `app/js/core/`.

Техническому читателю: [архитектура](docs/ARCHITECTURE.md) · [карта модулей](docs/CODEMAP.md) · [модель данных](docs/DATA_MODEL.md) · [native bridge](docs/NATIVE_BRIDGE.md) · [точка входа в документацию](docs/README.md) · [правила работы с репозиторием](AGENTS.md).

## Проверка и сборка для разработчиков

Для JS smoke-тестов нужен **Node.js 22**; Python проверяет структуру проекта и контракты. Команды:

```powershell
python tools/check_project.py
node tools/run_smokes.js
.\check_project.cmd --strict-node --no-pause
```

В [GitHub Actions](https://github.com/zeter1/ZeTer-OS/actions/workflows/ci.yml) на Windows выполняются компиляция Python и строгие проверки проекта. Полная упаковка EXE запускается отдельно — вручную (`workflow_dispatch`) либо для специально помеченных `[package]`-коммитов. Проверки исходников и packaged self-test **не заменяют** ручную проверку окна, файловых диалогов и сохранения на реальной Windows-машине.

Для локальной нативной сборки используйте [`build_exe.bat`](BUILD_EXE.md). Она создаёт `dist/ZeTer-OS/` с `ZeTer-OS.exe` и всеми ресурсами. `build_release.cmd` создаёт **другой формат** — portable ZIP для запуска через Python. Для прямой публикации веб-файлов на uCoz служит `prepare_web.cmd`; альтернативный ZIP-формат собирает `build_ucoz.cmd`. [Инструкция](docs/UCOZ.md) · [Проверки](docs/TESTING.md).

## Ограничения, помощь и безопасность

- **Prerelease:** релизы предназначены для тестирования; перед обновлением сохраните важные данные.
- **Нет цифровой подписи EXE:** Windows может показывать предупреждение о неизвестном издателе.
- **Разные среды:** в браузере нет части Windows-native-функций, а данные desktop/web разделены.
- **Без открытой лицензии:** публикация исходников в GitHub не означает разрешение на свободное использование, изменение и распространение кода.

Нашли воспроизводимый баг? Приложите версию, режим запуска, шаги и **обезличенный** диагностический фрагмент в [Issues](https://github.com/zeter1/ZeTer-OS/issues). Не публикуйте без проверки файлы `data/`, документы, архивы, токены и личные сведения. [SUPPORT.md](SUPPORT.md) · [SECURITY.md](SECURITY.md).
