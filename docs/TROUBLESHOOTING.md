# Диагностика ZeTer OS

Этот документ помогает безопасно найти причину проблемы. Не удаляй `data/`, IndexedDB, backup или PWA-кэш до того, как определён режим запуска и сохранена копия важных данных.

## ZeTer OS не запускается

1. Запускай `start_zeter_os.cmd`, `start_zeter_os.bat` или `run_zeter_os.py`, а не `app/index.html` двойным кликом.
2. Проверь `data/logs/zeter-os.log` и последнюю строку `FATAL`/`ERROR`.
3. Если Python сообщает, что `pywebview` отсутствует, установи зависимости из `requirements.txt`.
4. Убедись, что рядом с launcher существует `app/index.html`.

Не перемещай отдельный launcher без папки `app/`.

## Python-хранилище недоступно

Признаки: сообщение «Python-хранилище недоступно», данные сохраняются не в `data/` или вызов pywebview завершается ошибкой.

- Проверь, что окно открыто launcher-ом с адресом `index.html?native=1`.
- Проверь наличие `window.pywebview.api` после события `pywebviewready`.
- Найди ошибку метода в `data/logs/zeter-os.log`.
- Сверь метод с [NATIVE_BRIDGE.md](NATIVE_BRIDGE.md).

Не добавляй пустой `try/catch`, скрывающий ошибку bridge.

## Состояние не восстановилось

- В native-режиме источник восстановления — `data/zeter-os-state.json`.
- В browser-режиме источник — IndexedDB `zeter-os-primary-state`; это отдельное хранилище.
- Если показан экран «Не удалось прочитать данные ZeTer OS», запись уже заблокирована: сначала нажми «Повторить чтение» либо открой `data` и журналы для безопасной диагностики.
- Проверь JSON и лог чтения, не перезаписывая исходный файл.
- Перед восстановлением сохрани копию state и проверь подходящий файл в `data/backups/`.
- Для изменения формата следуй [DATA_MODEL.md](DATA_MODEL.md), а не исправляй пользовательский JSON вручную.

ZeTer OS не восстанавливает backup автоматически. Не удаляй повреждённый state до сохранения его отдельной копии и осознанного выбора проверенного backup/ZIP.

Если сохранение возвращает этап `primary-confirm`, проверь в `data/logs/zeter-os.log` запись `SAVE_ERROR`. До подтверждённой основной записи ZeTer OS не запускает пересборку Windows-копии, очистку payload или ротацию backups; прежний `zeter-os-state.json` должен остаться источником следующего запуска.

## Показывается старая версия интерфейса

- В browser/PWA-режиме проверь совпадение `ZETER_OS_VERSION` и `ZETER_CACHE`.
- Убедись, что новый JS/CSS-файл добавлен в `ZETER_ASSETS`.
- Запусти строгий checker; он проверяет version/cache и offline-ресурсы.
- В pywebview service worker не регистрируется, а локальный сервер отправляет no-cache headers. Поэтому сначала проверь, что запущена текущая папка проекта.

Не меняй cache-name отдельно от версии только ради обхода ошибки.

## Boot не завершается или глобал не загружен

Признаки: остаётся boot-screen, интерфейс пустой или console показывает `ZETER_* is not loaded`/`is not defined`.

Начиная с версии 3.56 ранний `boot-guard` заменяет бесконечную анимацию понятным экраном ошибки. В native-режиме первая фатальная JavaScript-ошибка или 30-секундный boot-timeout записывается как `CLIENT_ERROR` в `data/logs/zeter-os.log`.

1. Сохрани первую ошибку console и имя отсутствующего глобала.
2. Найди экспорт через `rg -n "window\.ZETER_ИМЯ" app/js/core`.
3. Проверь, что файл подключён в `app/index.html` раньше потребителя и присутствует в `ZETER_ASSETS`.
4. Запусти strict-check: он проверит порядок, зависимости, циклы, cache и syntax.

Не переставляй скрипты наугад: сначала установи реальную зависимость.

## Кнопка или действие перестало работать

- Найди одинаковый `data-action`, class или ID в `app/index.html`, builders и обработчиках `app/js`.
- Проверь ближайший delegated handler и не перекрывает ли элемент overlay с большим `z-index`.
- Сравни payload action с dispatcher/controller: имя, ID объекта, callback и error-path.
- Повтори действие клавиатурой, если соседний интерфейс её поддерживает.
- После переименования убедись, что старое имя отсутствует во всём `app/`.

Не добавляй второй обработчик, пока не подтверждено, почему не вызывается существующий.

## CSS не применяется или неожиданно перебит

1. Найди все определения selector командой `rg -n "selector" app/css app/js app/index.html`.
2. Проверь computed style, победивший файл, specificity и порядок `@import`.
3. Убедись, что правило находится в тематическом файле и ограничено корнем компонента.
4. Проверь обычный `1320×840` и узкий `1024×640`, длинный текст, scroll, focus и disabled.
5. Если проблема только в browser/PWA, проверь cache по разделу выше.

Strict-check подтверждает структуру CSS и карту файлов, но не заменяет визуальную проверку cascade.

## Native и browser ведут себя по-разному

- Зафиксируй URL/способ запуска и источник состояния: `data/zeter-os-state.json` или IndexedDB.
- В native проверь `?native=1`, событие `pywebviewready`, `window.pywebview.api` и лог метода.
- В browser проверь IndexedDB, console и service worker; Python API там отсутствует по контракту.
- Сравни ветки `shouldUseNativeStorage()` и `nativeStorageCall(...)`, не копируя пользовательские данные между режимами вручную.

## Checker сообщает, что Node.js не найден

- Обычная проверка может показать предупреждение и пропустить JS-синтаксис.
- Запускай `.\check_project.cmd --strict-node --no-pause`: wrapper ищет Node в `ZETER_NODE`, `PATH` и runtime Codex.
- Если Node лежит отдельно, задай `ZETER_NODE` полным путём к `node.exe`.

Не объявляй JS-проверку успешной, если Node фактически не запускался.

## Генерируемая документация устарела

Если `docs.generated` сообщает об устаревшей документации:

```powershell
python tools/update_docs.py --write
python tools/update_docs.py --check
python tools/check_project.py --strict-node
```

Генератор меняет только `MODULE_DEPENDENCIES.md` и отмеченный блок `CODEMAP.md`. Остальные документы обновляй вручную только по смыслу.

## Backup не импортируется

- Проверь формат JSON/ZIP и сообщение import validator.
- Учитывай лимиты из `app/js/core/config.js`.
- Не заменяй текущее состояние до успешной глубокой проверки нового.
- Проверь старый state на отдельной копии через migrate → save → reload.

## Windows-читаемая копия не обновилась

- `data/Рабочие столы/` — производная копия, создаваемая после native-сохранения.
- Проверь, что основная запись завершилась успешно и в логе есть `SAVE`/`WINDOWS_READABLE`.
- Проверь права записи и занятые файлы.
- Не восстанавливай canonical state из Windows-копии автоматически.

## Что приложить к отчёту об ошибке

- способ запуска;
- точное действие перед ошибкой;
- последнюю относящуюся запись из `data/logs/zeter-os.log`;
- режим хранения: native или browser;
- версию ZeTer OS;
- первую ошибку browser console и отсутствующий `ZETER_*`, если они есть;
- selector и победившее computed-правило для CSS-проблемы;
- снимки обычного и узкого окна из `work/ui-checks/` для визуальной проблемы;
- точный результат checker;
- что уже проверено и какие пользовательские данные были сохранены отдельно.
