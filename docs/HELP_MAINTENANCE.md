# Актуализация пользовательской справки ZeTer OS

Этот документ определяет, когда и как Codex обязан обновлять встроенную справку. Цель — чтобы обычный пользователь мог доверять описанию и выполнить реальный сценарий без чтения технической документации.

## Владелец и связанные файлы

| Область | Источник |
|---|---|
| Содержание, поиск, навигация и действия | `app/js/core/help-content.js` |
| Кнопка первого запуска | `app/js/core/first-run-ui-utils.js`, `app/js/core/shell-ui-utils.js` |
| Размер окна и app-id | `app/js/core/app-catalog.js` |
| Передача `openApp` и версии | `renderHelpApp` в `app/js/app.js` |
| Оформление и адаптивность | `app/css/40-app-foundation.css` |
| Постоянный контракт | `tools/smoke_help_content.js` |
| Карты владельцев и UI-hooks | `tools/code_owners.json` |

Не создавай второй источник пользовательской справки в `app.js`, HTML или документации. Встроенное содержание живёт в `ZETER_HELP_CONTENT`; этот документ описывает только процесс его поддержки.

## Когда обновление обязательно

Сверь и при необходимости измени справку, если затронуто хотя бы одно из следующего:

- добавлено, удалено или переименовано приложение либо видимое действие;
- изменился основной пользовательский сценарий, порядок шагов или место кнопки;
- появилась или изменилась горячая клавиша, drag/drop, контекстное меню или навигация;
- изменились удаление, восстановление, права доступа или другое важное ограничение;
- изменился путь хранения, desktop/browser-режим, состав папки `data` или Windows-копий;
- изменились import/export, backup, шифрование, точка восстановления или формат файла;
- исправлена ошибка, из-за которой прежняя инструкция стала неточной;
- новая возможность достаточно важна, чтобы пользователь мог искать её по названию в справке.

Внутренний рефакторинг, переименование приватной функции и оптимизация без видимого изменения не требуют искусственной правки текста.

## Источники истины

Не описывай возможности по памяти. Сначала проверь текущий код и относящиеся документы:

1. Найди владельца через `python tools/find_owner.py "пользовательский сценарий"`.
2. Проверь реальную разметку, `data-*`, обработчик действия и состояние ошибки/ограничения.
3. Сверь список приложений с `app/js/core/app-catalog.js`.
4. Для desktop-хранения и Windows-копий используй [NATIVE_BRIDGE.md](NATIVE_BRIDGE.md) и [../README_PYTHON.md](../README_PYTHON.md).
5. Для state/import/storage используй [DATA_MODEL.md](DATA_MODEL.md), для полного сценария — [SCENARIO_MAP.md](SCENARIO_MAP.md).

Если код и старый текст расходятся, источником истины является проверенное текущее поведение кода. Не сохраняй в справке устаревшую возможность ради совместимости текста.

## Как писать справку

- Пиши простыми русскими словами и начинай с действия пользователя.
- Указывай точные названия кнопок, меню, приложений, путей и форматов.
- Для многошаговой операции давай порядок от входа до подтверждённого результата.
- Отдельно выделяй необратимость, замену данных, пароль без восстановления и различия desktop/browser.
- Не обещай автосохранение, восстановление или внешний файл, если этот результат не подтверждён кодом.
- Добавляй поисковые слова в заголовок, краткое описание или `keywords`, чтобы тему можно было найти обычным запросом.
- Кнопка `data-help-app` должна ссылаться только на существующий app-id из `app-catalog.js`.
- Не перегружай первый экран: быстрый маршрут должен вести в подробные тематические разделы.

## Порядок изменения

1. Определи затронутый раздел в `HELP_SECTIONS`; расширяй существующую тему, если ответственность та же.
2. Добавь новую тему только для отдельного пользовательского сценария. Новый раздел нужен для крупной самостоятельной области.
3. Обнови предупреждение или troubleshooting, если изменение влияет на сохранность данных либо типичный сбой.
4. Если изменилось первое знакомство, синхронно обнови текст и hook в `first-run-ui-utils.js`, обработчик в `shell-ui-utils.js` и smoke.
5. Если изменились публичные методы `ZETER_HELP_CONTENT`, app-якорь или UI-hooks, обнови `tools/code_owners.json` и ручное описание в [CODEMAP.md](CODEMAP.md).
6. После core/manifest-изменений выполни генерацию навигационных документов.

## Проверка

Минимальные автоматические команды:

```powershell
node --check app/js/core/help-content.js
node --check app/js/core/first-run-ui-utils.js
node --check app/js/core/shell-ui-utils.js
node tools/smoke_help_content.js
python tools/update_docs.py --write
python tools/update_docs.py --check
.\check_project.cmd --strict-node --no-pause
```

Если `python` или `node` не находится через `PATH`, используй runtime, который находит Windows-wrapper проекта.

Ручная проверка:

1. На чистом первом запуске кнопка называется «Посмотреть возможности» и открывает справку.
2. Поиск находит тему по названию, синониму и важному формату; пустой результат показывает понятное сообщение.
3. Навигация прокручивает к каждому разделу, Esc очищает поиск, темы раскрываются клавиатурой.
4. Кнопки внутри тем открывают правильные приложения.
5. В обычном и узком окне нет обрезанного текста, двойной прокрутки и недоступных действий.
6. Предупреждения об удалении, `data`, browser-режиме, импорте и пароле соответствуют текущему коду.

Полная матрица и единая строгая команда находятся в [TESTING.md](TESTING.md).
