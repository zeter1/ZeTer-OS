# Архитектура ZeTer OS

ZeTer OS — локальное Windows-приложение с HTML/CSS/JavaScript-интерфейсом внутри pywebview. Этот документ описывает устойчивые границы проекта. Текущие владельцы перечислены в [CODEMAP.md](CODEMAP.md), а повседневный порядок JS/CSS-работы — в [FRONTEND_WORKFLOW.md](FRONTEND_WORKFLOW.md).

Фактический порядок и граф `window.ZETER_*` генерируются в [MODULE_DEPENDENCIES.md](MODULE_DEPENDENCIES.md); значения предметных терминов зафиксированы в [GLOSSARY.md](GLOSSARY.md).

## Главный принцип

Пользовательское состояние важнее внутренней структуры кода. Рефакторинг должен сохранять формат данных, миграции, публичные глобалы, pywebview API и текущее поведение интерфейса.

## Слои

### Python launcher

`run_zeter_os.py`:

- запускает локальный HTTP-сервер на `127.0.0.1`;
- открывает интерфейс в pywebview;
- предоставляет `NativeStorageApi`;
- атомарно сохраняет состояние в `data/`;
- создаёт резервные и Windows-читаемые копии;
- пишет диагностический лог.

Публичный контракт этого слоя описан в [NATIVE_BRIDGE.md](NATIVE_BRIDGE.md).

### Web shell

- `app/index.html` задаёт DOM-оболочку и порядок JS-зависимостей.
- `app/js/core/*.js` содержит предметные, чистые и UI-модули.
- `app/js/app.js` связывает модули с текущими `state`, DOM, окнами, сохранением и верхнеуровневыми событиями.
- `app/css/style.css` остаётся единственной CSS-точкой входа и импортирует смысловые CSS-модули.

### Storage and data

- В Python-режиме источник восстановления — `data/zeter-os-state.json`.
- В браузере основное состояние хранится в IndexedDB.
- `localStorage` используется для маленького снимка настроек, миграции старого состояния и аварийного browser-fallback.
- `data/Рабочие столы/` — производная Windows-копия, а не источник восстановления.

Формат и правила совместимости описаны в [DATA_MODEL.md](DATA_MODEL.md).

## Направление JavaScript-зависимостей

Порядок загрузки идёт от базовых контрактов к интеграции:

```text
version → config → core utils → предметные/data modules → UI modules → app.js
```

Core-модуль может использовать только глобалы, подключённые раньше него в `app/index.html`. Циклические зависимости между core-модулями запрещены.

Порядок проверяется автоматически по реальным ссылкам `window.ZETER_*`, а не только по ручному списку скриптов.

Каждый core-файл экспортирует один публичный глобальный объект вида `window.ZETER_*`. `app.js` получает этот объект в верхней части файла и падает с понятной ошибкой, если обязательная зависимость не загружена.

## Граница app.js и core

В core-модуль выносятся:

- чистые вычисления и normalizers;
- построение view-model;
- повторно используемая HTML/DOM-сборка;
- предметные операции над переданными объектами;
- логика, которую можно проверить узким smoke-тестом.

В `app.js` остаются:

- запуск и связывание модулей;
- владение текущим `state` и runtime UI;
- верхнеуровневые event handlers;
- вызовы сохранения, открытия окон и системных API;
- тонкие адаптеры, передающие callbacks и актуальные зависимости.

Модуль не должен скрыто захватывать изменяемый `state`, если его можно передать аргументом. Логика не должна одновременно существовать в core и `app.js`.

## Состояние и миграции

- Новые поля добавляются через defaults/normalizers.
- Старые поля читаются, пока существует поддерживаемый пользовательский формат.
- Миграция выполняется до использования загруженного состояния.
- Удалять старые миграции без отдельного решения нельзя.
- Операции удаления должны очищать ссылки в окнах, вкладках, закреплениях, стикерах, истории и производных копиях.
- Импортируемый backup проходит лимиты и глубокую проверку до замены текущего состояния.

## CSS и PWA

Порядок `@import` в `app/css/style.css` значим: поздние файлы могут намеренно переопределять ранние. Новый CSS добавляй в подходящий существующий файл; новый файл создавай только для отдельной устойчивой области.

Любой новый обязательный JS/CSS-ресурс должен быть:

1. подключён из `index.html` или `style.css`;
2. добавлен в `ZETER_ASSETS` внутри `app/service-worker.js`;
3. проверен через `tools/check_project.py`.

Имя PWA-кэша должно совпадать с версией интерфейса. В pywebview/native-режиме service worker не регистрируется.

## Контракты, которые нельзя ломать без миграции

- порядок core-скриптов до `app.js`;
- один публичный `window.ZETER_*` на core-модуль;
- `window.ZETER_OS_VERSION`, config/storage IDs и PWA cache-name;
- структура основного state и записи состояния;
- ID файловой системы и связи между объектами;
- методы и envelope `NativeStorageApi`;
- имена важных файлов внутри `data/`.

Полный перечень текущих глобалов находится в [CODEMAP.md](CODEMAP.md). Команды и ручные сценарии — в [TESTING.md](TESTING.md).
