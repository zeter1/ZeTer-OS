# Проверка ZeTer OS

Это единственный источник команд, постоянных smoke-тестов и ручных сценариев. Начинай с узкой проверки; после структурного JS/CSS-, resource-, data-, bridge-, docs- или checker-изменения выполняй полный strict-check.

## Единая строгая команда

```powershell
.\check_project.cmd --strict-node --no-pause
```

Windows-wrapper ищет Python в `ZETER_PYTHON`, `.venv`, `py`, `python` и runtime Codex. Node берётся из `ZETER_NODE`, `PATH` или runtime Codex. Указывай переменные окружения как полный путь к executable; пользовательские абсолютные пути не записывай в проект.

Успешный итог содержит только `0 warnings` и `0 failures`. Строгий режим проверяет структуру, документацию, Python/JS syntax, запускает весь постоянный JavaScript scenario smoke-suite, герметичный Python native-smoke и smoke сборщика релиза.

Все файлы находятся в `tools/`; `run_smokes.js` запускает их последовательно из корня проекта. Одноразовый тест не сохраняй. Постоянный риск добавляй отдельным небольшим smoke либо в существующий профильный файл.

Дополнительно native-smoke проверяет исчезновение backup во время подсчёта размеров, видимость других ошибок доступа, пропуск неизменных DOCX с разными ZIP-датами, изменённые XML/изображения, extra/duplicate ZIP entries, восстановление повреждённого/неподдерживаемого target, сохранность основной записи и прежнего DOCX при отказе замены, точность контекста удаления старого файла. Problem-log smoke проверяет parent/root-корреляцию, поздний успех после sampling, `archiveOk`, slow-контекст, первоначальную identity при смене дня и drift, неполные исходники, mocked frozen hash, сохранность legacy incomplete и публикацию сводки при максимальном контексте. Эти проверки используют только искусственные данные; реальный установленный EXE ими не проверяется.

При запрете записи в системный TEMP задай `TEMP` и `TMP` процессу проверки на отдельный доступный каталог внутри игнорируемого `work/`. Это перенаправляет тестовые TemporaryDirectory; native state по-прежнему перенаправляется через `configure_temp_data` до конструктора API. Если Windows `py` не находит Python, задай `ZETER_PYTHON` по фактическому пути существующего интерпретатора. Первый отказ окружения сохраняется как отдельный результат, а не объявляется продуктовым багом.

Для узкого smoke используй минимальные заглушки реальных зависимостей и проверь успех, пустой/граничный ввод, ожидаемую мутацию, error/fallback и callback-порядок action flow.

Strict-check запускает `smoke_managed_file_native.py`, `smoke_problem_logs.py` и `smoke_release_builder.py` отдельными Python-процессами через тот же интерпретатор, которым запущен checker. Native-smoke ограничен 60 секундами, расширенный problem-log smoke — 90 секундами, release-smoke — 30 секундами; ненулевой код завершения или timeout считается общей ошибкой проверки. Дополнительный бюджет диагностики нужен для максимального контекста, дневной смены identity и прежних многопроцессных проверок с реальными атомарными записями.

## Что проверяет strict-check

- обязательные файлы, документы, Markdown-ссылки и контракт `AGENTS.md`;
- ресурсы `index.html`, порядок/граф core и PWA cache;
- один `window.ZETER_*` на core и ручную core-карту `CODEMAP.md`;
- app.js-якоря `CODEMAP.md`;
- manifest владельцев, его файлы/якоря, поисковый CLI и все generated navigation docs;
- JavaScript ↔ `NativeStorageApi`;
- чистую CSS-точку входа, существование/порядок CSS-карты и cache coverage;
- Python/JavaScript syntax, включая smoke-файлы;
- весь постоянный JavaScript scenario smoke-suite, профильный Python smoke managed-файлов и smoke сборщика релиза.

## Воспроизводимая UI-проверка

1. Запиши сценарий, режим `native`/`browser`, версию и ожидаемый результат.
2. Для native запусти `start_zeter_os.cmd`. Базовый размер окна — `1320×840`, узкий — минимальный `1024×640`.
3. Открой изменённый сценарий с обычными данными, пустым состоянием, длинным русским текстом и большим списком.
4. Проверь mouse, keyboard, touch-поведение при наличии, hover/focus/active/disabled, loading/error, scroll, clipping, overlap и z-index.
5. Если данные сохраняются, закрой приложение, запусти снова и повторно открой объект.
6. Для browser/PWA при необходимости запусти из корня `python -m http.server 8000 --directory app` и открой `http://127.0.0.1:8000/`; не используй реальные native-данные как фикстуру.
7. Сохраняй временные снимки как `work/ui-checks/YYYY-MM-DD/сценарий-normal.png` и `сценарий-narrow.png`. Папка игнорируется Git.

Если GUI не открывался, передай эти шаги как непроверенные, а не как пройденные.

Категории автоматизаций: создать две категории → назначить им разные правила → запустить правила → выбрать каждую категорию и сверить её список/историю/сводку. Переименовать категорию и повторить после перезапуска. Удаление отменить, затем проверить отдельно удаление только категории и удаление с правилами: чужие правила, файлы/заметки и история должны сохраниться; ожидающие запуски удалённых правил — отмениться. При отказе сохранения весь набор возвращается к прежнему состоянию. Проверить изоляцию рабочих пространств и round-trip импорта. Для файлового примера выбрать заметку → «Проверить автоматизацию» → результат остаётся, выбор пуст, действия не выполнены; повторная проверка недоступна до нового выбора. Проверить оба пути: редактор и проверка сохранённого правила.

Для выбора файла в автоматизациях отдельно проверь на обычной и узкой ширине: рабочий стол с пользовательским названием подписан именно как рабочий стол; файлы из подпапок не показаны при выборе его корня, но видны при «Любая папка ZeTer OS». Выбери заметку в подпапке: «Открыть заметку» открывает её, «Открыть папку объекта» — её родителя, не рабочий стол. Удали пример и убедись, что переход не подменяется другим объектом. Сменив триггер с файла на событие и обратно, проверь соответствующие пояснения переменных и пример подстановки, включая `{file.name}` для заметки в файловом триггере.

## Ручная матрица

Обновление EXE из GitHub Releases: использовать две отдельные сборки A/B с разными версиями и искусственными данными/контрольными файлами. При обнаружении B сверить запись в центре уведомлений и предложение около «О ZeTer OS», «Позже», ручную проверку и повтор без дубликатов; в обоих уведомлениях «Что нового» открывает точный GitHub CHANGELOG, «Обновить вручную» — окно с шестью шагами, ссылками на репозиторий/Releases и переносом длинных имён на узкой ширине. Проверить загрузку/отмену, отказ сохранения без закрытия, двойное нажатие, SHA/ZIP/manifest, изменённый файл программы, конфликт с чужим файлом, настоящий junction, сбой посреди замены и восстановление без staging. Для успеха сверить контрольные суммы установленных файлов, изолированную WebView2-проверку/nonce, commit и точный новый процесс после обычного перезапуска; при отказе проверки старые файлы и контрольные данные сохраняются. Source/PWA не устанавливают EXE. Полный smoke создаёт только собственные fixtures в `work/update-tests`; Windows sandbox может запрещать `mklink /J`, это отдельный environment FAIL и требует того же ограниченного smoke вне sandbox. Подробности — [UPDATES.md](UPDATES.md).

В инструкции «Обновить вручную» проверить три текстовые ссылки внизу страницы и кнопки сверху. Выделить обычный текст и отдельно URL → щёлкнуть по выделенному левой кнопкой → «Копировать» → вставить и сверить пробелы/переносы. Повторить с ПКМ и Ctrl+C; щелчок вне выделения позволяет начать новое выделение. Проверить узкое окно и сообщение при отказе clipboard. Browser-проверка не подтверждает native clipboard и запуск внешнего браузера в Windows.

Окно «О ZeTer OS»: открыть с верхней панели → сверить текущую версию, описание, «Что нового», «Обновления системы», «Репозиторий» и все контакты → выделить текст мышью → ПКМ → «Копировать» → вставить в тестовое поле; проверить также Ctrl+C. Проверить ссылки через внешнее открытие в browser/native, перенос длинных адресов и прокрутку при узком окне, закрытие/повторное открытие. В Настройках нет карточек «О системе» и «Разработчик». Проверка browser не подтверждает native clipboard и запуск внешнего браузера в Windows.

## Промпты

`node tools/smoke_prompt_library.js` проверяет проекты и категории внутри проектов, точный текст без trim, CRUD, поиск, избранное, принадлежность категорий, независимость рабочих столов и откат при отказе записи. Import/ZIP и архив рабочего стола проверяются дополнительно профильными smoke.

Ручной сценарий: открыть «Промпты» из Пуска/Приложений, создать два проекта и категории с одинаковым названием в разных проектах; сохранить отдельные название и многострочный текст с пробелами. «Скопировать промпт» должен дать ровно текст, без названия и дополнительных строк. Проверить поиск, избранное, перенос между проектами, удаление категории с сохранением записей и удаление непустого проекта с переносом в общий раздел либо удалением всех его промптов. Проверить добавление без проектов, скрытый блок категорий, окно создания/переименования в стиле ZeTer OS, полную focus-обводку выбора проекта, эксклюзивные галочки, отмену/Escape/Tab/Enter, отказ записи с повтором и параллельным сохранением. Открыть второе окно, сохранить черновик при обновлении библиотеки, перезапустить и сверить данные. На другом рабочем столе библиотека пустая; удаление стола без выбранных групп сохраняет промпты в архиве, выбор prompts удаляет только эту группу. Проверить ширины 980px и 460px, светлую/тёмную тему, клавиатуру, ошибку записи и копирования. При FAIL нужны точные шаги, видимая ошибка и console без личных текстов.

## Ссылки

`smoke_link_library.js` проверяет CRUD, порядок/удаление категорий с сохранением записей, избранное/поиск, Windows-дубли, unsafe targets/IDs, escaping, production import validator, настоящий ZIP/manifest round-trip всех библиотек и отказ сохранения → повтор без потери независимого state. Два synthetic workspace подтверждают изоляцию CRUD/favorite/category и switch перед очередью/во время сохранения. Migration-smoke проверяет старое состояние, однократный перенос legacy root в исходный стол и recovery при конфликте.

Ручная проверка: открыть Ссылки из Пуска/Приложений, добавить сайт, Windows-путь и внутренний объект; создать категорию из формы, переименовать/переставить/удалить, проверить избранное и поиск. В двух окнах проверить сохранение черновика и обновление списка одного стола, затем создать другой рабочий стол и подтвердить пустую отдельную библиотеку; добавить свою запись/категорию/избранное, перезапустить и проверить оба стола. Проверить 980px и 460px ширины, длинный адрес, клавиатурный focus, светлую/тёмную тему. Проверить native открытие и executable confirmation отдельно; в браузере Windows-путь должен оставаться доступным для копирования. При FAIL приложить точные шаги, скриншот, текст видимой ошибки и browser console без личных адресов.

Адрес в карточке открывает ту же цель, что и «Открыть» (мышь/Enter/Space). Шестерёнка каждой категории показывает переименование, закрепление/открепление, порядок внутри своей группы и удаление; настройки не переключают выбранный фильтр. Проверить Escape с возвратом фокуса и щелчок снаружи; закрепление сверху → reload → открепление, сохранность черновика при действиях с другой категорией и возврат ссылок в «Без категории» при удалении. `smoke_link_library.js` проверяет pinned JSON/ZIP round-trip, invalid flag, отказ сохранения с откатом, разделение порядка и независимость рабочих столов. В узком окне форма и список прокручиваются целиком.

Булавка карточки закрепляет ссылку только в текущем разделе. Для каждой из четырёх групп (all/favorites/uncategorized/category) проверить подъём последней карточки, отсутствие pin в других разделах, query и reload; Space сохраняет фокус кнопки. Перенести запись, удалить категорию и снять избранное: pin исчезает только из раздела, в который запись больше не входит. JSON/ZIP/import, legacy-флаг и отказ сохранения проверяются отдельно.

Удаление рабочего стола: `smoke_state_migration.js` проверяет отмену, staged отказ→повтор, архивирование без переноса на основной стол, сохранность исходных ID/категорий/проектов/избранного и скрытого дерева, выборочное удаление, независимые изменения, compensation success/failure, active runtime до release barrier. Import-smoke проверяет глубину архивов и unsafe payload paths. `smoke_desktop_backup_native.py` проверяет desktop ZIP с byte-identical payload, отмену, traversal/missing, atomic failure, читаемую архивную копию и retention после замены активного состояния; strict-check запускает этот тест автоматически.

Ручная/isolated browser проверка: дополнительный стол с документом, событием и ссылкой → × → все флажки выключены → cancel/Escape/Delete/Ctrl+Z без изменений. Выбрать календарь, скачать ZIP: проверить desktop.json со всеми группами (включая календарь), документом и без чужих столов; скачивание не закрывает диалог. Удалить: календаря в retained архиве нет, ссылка и документ остались в archivedDesktops, основной стол их не получил. Reload сохраняет архив. В Windows проверить выбранный путь ZIP, реальное вложение и data/Архив рабочих столов/<id>/desktop.json. Отдельно выбрать links на другом столе: выбранные ссылки исчезают, основной стол остаётся прежним. Проверить маленькое окно, focus/Space/Enter, ошибку и отмену экспорта. При FAIL нужны шаги, выбранные группы, видимая ошибка и console без личных данных.

Подсчёты: добавить РКО → изменить поля → перетащить за ручку на выбранную карточку внутри окна → «Выше»/«Ниже» и границы списка → убрать и вернуть с прежним вводом → перезапустить и проверить порядок. Также: пустой список, поиск без результатов, нули/неверный ввод, два окна и другой стол, узкая ширина, отказ сохранения и повтор, JSON/ZIP round-trip.

Подсчёты, размеры и перетаскивание: 1320×840 и широкое окно — две карточки в ряд, 460px — одна; захват за ⠿ показывает целую движущуюся карточку и место вставки.
