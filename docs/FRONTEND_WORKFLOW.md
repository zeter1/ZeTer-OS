# Frontend-workflow ZeTer OS для Codex

Этот документ нужен для структурных или многосоставных изменений `app/js` и `app/css`. Для небольшой правки у уже известного владельца сразу переходи к его коду и рецепту из [EDITING_GUIDE.md](EDITING_GUIDE.md). Не читай всю документацию автоматически.

## Результат вайбкодинга

Пользователь описывает результат, а Codex сам находит владельца, собирает законченный сценарий и доводит его до проверенного состояния. Подтверждение каждого безопасного шага не требуется. Короткий план нужен при нескольких подсистемах, новом ресурсе, заметном UI-изменении, state, storage или native bridge.

Вайбкодинг не разрешает угадывать архитектуру, менять соседнее поведение, скрывать ошибку, использовать реальные `data/` как тест или объявлять GUI проверенным без запуска.

## Цикл принятия решения

1. Проверь Git и относящийся diff; сохрани согласованную рабочую базу.
2. Найди сценарий командой `python tools/find_owner.py "запрос"` и по [SCENARIO_MAP.md](SCENARIO_MAP.md), затем подтверди владельца через [CODEMAP.md](CODEMAP.md), вызовы, зависимости, selectors и `data-*`.
3. Определи полный пользовательский путь: ввод → модель/view-model → действие → DOM → сохранение или ошибка.
4. Расширь существующего JS/CSS-владельца. Новый файл создавай только для отдельной устойчивой ответственности.
5. Сразу выполни узкую синтаксическую и поведенческую проверку.
6. Для UI фактически проверь состояния из [TESTING.md](TESTING.md). После структурного изменения запусти полный strict-check и просмотри diff.

## Выбор JavaScript-владельца

`app/js/app.js` — composition root. В нём остаются текущий `state`, DOM, boot, сохранение, окна, dialogs, `openApp`, native-интеграция, controller-конфигурации и тонкие callback-adapters.

- Pure helpers, models, parsing и normalizers размещай в профильном `*-utils.js`.
- HTML/view-model, DOM binding и UI-actions — в профильном `*-ui-utils.js`.
- Многошаговый runtime-сценарий с callbacks — в controller-модуле своей подсистемы.
- Текущий state/DOM/save/open/native передавай из `app.js` параметрами.

Каждый core-файл экспортирует один `window.ZETER_*`. Зависимости загружаются раньше потребителя. Реализация не должна одновременно существовать в core и `app.js`.

Пользовательский текст вставляй через существующие `escapeHtml`, `safeAttr` или профильные безопасные builders. Не используй `eval` и непроверенный HTML.

## Выбор CSS-владельца

`app/css/style.css` — только упорядоченные `@import`; точный порядок и области перечислены в `CODEMAP.md` и проверяются автоматически.

- Ищи все определения selector во всём `app/css`.
- Используй существующие custom properties и тематический файл компонента.
- Не складывай обычные правила в `80-overrides.css` и не добавляй `!important`, если достаточно правильного cascade/specificity.
- Ограничивай локальное правило корневым классом приложения.
- Статическое оформление держи в CSS; inline-style оставляй для координат, размеров и других runtime-значений.
- Сохраняй focus, contrast, touch-area, перенос длинного текста и предсказуемый scroll.

## Законченный UI-сценарий

Согласуй данные, разметку, мышь/клавиатуру/touch, loading/empty/error/disabled, CSS и повторное открытие сохраняемых данных. Не переименовывай class, `data-*` или callback contract без поиска всех потребителей.

Если изменение видно обычному пользователю, перед сдачей сверь затронутый сценарий с `app/js/core/help-content.js`. Новая возможность, переименованное действие, изменившаяся горячая клавиша, путь хранения, формат, import/export, backup или ограничение должны быть отражены по правилам [HELP_MAINTENANCE.md](HELP_MAINTENANCE.md). Внутренняя перестройка без изменения поведения не требует формального переписывания справки.

## Особые границы

- State, migration, import/export и storage: сначала [DATA_MODEL.md](DATA_MODEL.md), затем профильный smoke и round-trip.
- Python/pywebview: сначала [NATIVE_BRIDGE.md](NATIVE_BRIDGE.md), затем Python syntax и отдельные native/browser ветки.
- Новый core: `index.html`, `service-worker.js`, `REQUIRED_SCRIPT_ORDER`, `tools/code_owners.json`, ручная карта `CODEMAP.md` и generated docs.
- Новый CSS: `style.css`, PWA-кэш и CSS-карта `CODEMAP.md`.
- PWA cache-name меняется только вместе с версией интерфейса.

Точные рецепты находятся в [EDITING_GUIDE.md](EDITING_GUIDE.md), команды и матрица проверок — в [TESTING.md](TESTING.md).
