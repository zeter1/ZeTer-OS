# Документация ZeTer OS

Это основная точка входа в техническую документацию. Источник истины — текущий код. Выбирай документ по задаче и не читай весь комплект для небольшой локальной правки.

## Начало работы над задачей

1. Прочитай [правила проекта](../AGENTS.md), проверь `git status --short` и diff затронутых файлов. Незакоммиченные изменения входят в текущую рабочую базу; история Git не заменяет её.
2. Определи режим: объяснение/аудит, диагностика или изменение. Для бага отдели наблюдаемый сбой от гипотезы и найди проверку, которая различит возможные причины.
3. Найди владельца через `python tools/find_owner.py "запрос"`. Для frontend результат содержит JS, CSS, state, smoke и ручной сценарий; для Python — модуль, найденные определения/методы, связанные JS, контракты и smoke. Поиск Python читает AST без импорта приложения и охватывает зарегистрированных владельцев, а не все функции репозитория. Подтверди вызовы в коде по [рецепту поиска](EDITING_GUIDE.md#быстрый-поиск).
4. Прочитай один профильный контракт из таблицы ниже. Для небольшой правки достаточно владельца, его потребителей и ближайшей проверки; расширяй контекст только при пересечении границ.
5. Перед выполнением кода проверь [изоляцию данных](TESTING.md#безопасность-запуска-проверок). После правки выполни профильные проверки, затем полный strict-check и просмотр diff по [TESTING.md](TESTING.md).

## Что представляет собой проект

Одна web-оболочка работает в браузере/PWA и внутри Windows-приложения. [ARCHITECTURE.md](ARCHITECTURE.md) описывает запуск, связи слоёв и границы хранения; [DATA_MODEL.md](DATA_MODEL.md) — какой экземпляр данных считается основным. `app.js` связывает текущий state и системные действия с предметными core-модулями. Python предоставляет локальное хранение и native-возможности; установка обновления EXE — отдельный процесс по [UPDATES.md](UPDATES.md).

Запуск из исходников: [README_PYTHON.md](../README_PYTHON.md). Сборка Windows EXE: [BUILD_EXE.md](../BUILD_EXE.md). Команды сборки/публикации имеют собственные выходные каталоги и внешние границы; обычная правка кода не означает запуск сборки, обновление установки или публикацию.

## Ответственность документов

- `FRONTEND_WORKFLOW.md` — решения по границам JS/CSS, выбор владельца и критерий законченного сценария.
- `EDITING_GUIDE.md` — точные механические рецепты и команды поиска.
- `ARCHITECTURE.md` — устойчивые слои и контракты, без истории рефакторингов.
- `CODEMAP.md` — ручная карта назначений и поисковых якорей; только отмеченная техническая сводка генерируется.
- `MODULE_DEPENDENCIES.md` — полностью генерируемый порядок, глобалы и зависимости core-модулей.
- `SCENARIO_MAP.md`, `CORE_API_INDEX.md`, `UI_CONTRACTS.md` и `STATE_LIFECYCLE.md` — генерируемые поисковые индексы; их источник — `tools/code_owners.json` и текущий JS.
- `DATA_MODEL.md` и `NATIVE_BRIDGE.md` — контракты совместимости данных и JavaScript ↔ Python.
- `HELP_MAINTENANCE.md` — обязательные триггеры, источники истины и проверка пользовательской справки.
- `TESTING.md` — единственный владелец команд, постоянных smoke-тестов и ручной матрицы.
- `UPDATES.md` — канал обновлений, упаковка Windows-дистрибутива, публикация и восстановление; инструкция сборки EXE остаётся в `BUILD_EXE.md`.
- `TROUBLESHOOTING.md` и `GLOSSARY.md` — диагностика и единые термины.

Один факт должен иметь одно основное место. В остальных документах давай ссылку, а не копируй большой раздел.

История изменений имеет одного владельца — [CHANGELOG.md](../CHANGELOG.md). [RELEASE_NOTES_RU.md](../RELEASE_NOTES_RU.md) нужен CI как краткий текст конкретного Windows-релиза; обновляй его при подготовке сборки по [UPDATES.md](UPDATES.md), не дублируй в нём историю проекта и не требуй его изменения для обычной задачи.

## Ручные и генерируемые документы

| Что изменилось | Где править источник |
|---|---|
| Сценарий, UI-hook, путь state, связь с smoke | `tools/code_owners.json`; ориентир — существующая запись близкого сценария |
| Публичный core API или зависимости | Реальный JS и порядок скриптов в `app/index.html`; индекс извлекается из исходников |
| Python-модуль, класс/функция, связанные JS, документация и smoke | `python_owners` в `tools/code_owners.json`; методы выбранного класса извлекаются из AST |
| Ответственность core/CSS или native/build entrypoint | Ручная часть `CODEMAP.md` |
| Контракт поведения, данных, bridge или проверки | Профильный документ из таблицы выше |
| Реализованное пользовательское действие | `app/js/core/help-content.js` по `HELP_MAINTENANCE.md` |

Генератор обновляет целиком `MODULE_DEPENDENCIES.md`, `SCENARIO_MAP.md`, `CORE_API_INDEX.md`, `UI_CONTRACTS.md`, `STATE_LIFECYCLE.md` и только блок `BEGIN GENERATED CORE SUMMARY` внутри `CODEMAP.md`. Остальная часть `CODEMAP.md` ручная.

После изменения источников обнови карты через `tools/update_docs.py` по [TESTING.md](TESTING.md). Не редактируй generated-файлы и блок `BEGIN GENERATED CORE SUMMARY` вручную. `--check` подтверждает соответствие генератору, но не полноту ручного описания и не поведение GUI. API-индекс — поисковая карта имён; перед изменением сохранения, удаления или восстановления прочитай [контракты критических операций](DATA_MODEL.md#контракты-критических-операций).

Если карта расходится с кодом, сначала проверь реального владельца/вызов, затем исправь ручной источник и перегенерируй индекс. Планы в `docs/superpowers/` описывают намерения на момент задачи; текущее поведение устанавливается по коду и проверкам. Записи о старых успешных тестах не подтверждают текущую рабочую копию.

## Когда обновлять

- Измени ручное описание `CODEMAP.md`, если изменился владелец функции, ответственность модуля, CSS-область или поисковый якорь.
- После изменения core-модулей или `tools/code_owners.json` выполни `python tools/update_docs.py --write`; генерируемые карты вручную не редактируй.
- Обнови `FRONTEND_WORKFLOW.md`, только если изменился общий JS/CSS-процесс; `EDITING_GUIDE.md` — если изменился конкретный рецепт.
- Обнови `ARCHITECTURE.md` при изменении устойчивой границы, `DATA_MODEL.md` — формата/миграции, `NATIVE_BRIDGE.md` — публичного Python API.
- Сверь пользовательскую справку по [HELP_MAINTENANCE.md](HELP_MAINTENANCE.md), если изменился видимый сценарий, приложение, название действия, горячая клавиша, путь данных, формат, backup/import или важное ограничение.
- Обнови `TESTING.md`, если изменилась команда checker’а, smoke или ручной сценарий; повторяющуюся диагностику добавляй в `TROUBLESHOOTING.md`.
- `AGENTS.md` меняй только при изменении правил агента, а не после обычной функции или визуальной правки.
